# 健康医院专家门诊停诊、转诊与加号管理说明

本文档为虚构的 RAG 检索测试资料，不代表真实医生排班或号源政策。所有实时医生、日期和号源必须通过医院业务接口查询，不能从本文档或模型记忆推断内部 ID。

## 一、排班与号源

专家门诊排班发布后仍可能因临床任务、会议或其他原因调整。页面展示的医生姓名和出诊日期属于查询结果快照，患者准备预约时仍需重新核对实时号源。

候选列表中的“第一位、第二位”只在对应结果集内有意义。用户切换本周、下周或其他科室后，不能让模型根据先前文本猜测 doctorId 或 scheduleSlotId。

## 二、医生停诊

医生确认停诊后，系统会根据预约状态通知受影响患者。停诊不是患者爽约。已经预约的患者可以按照通知查看退费、改约或其他安排，但系统不会自动把患者转到任意同科室医生名下。

患者口头说“换一个医生也行”仍然需要展示真实候选并让患者明确选择。多个医生或多个时段都可用时，模型不能自行挑选。

## 三、改约

改约通常包含释放原预约和建立新预约两个业务结果。只有看到新预约成功，才能认为改约完成。原预约取消成功但新号源被占用时，应明确说明当前状态，不能声称已经自动换好。

写操作前必须重新查询原预约和目标号源。聊天中的历史候选只用于知道患者指的是哪一个对象，不能作为号源仍有库存的证明。

## 四、转诊建议

医生建议患者到另一科室就诊，不等于系统已经替患者挂号。患者仍需查询目标科室、医生和号源。院内转诊单、门诊预约和出院转诊材料也是不同业务。

转诊建议中出现医生姓名时，如果实时排班不存在该医生号源，应提示查询不到，不能使用模型生成的 ID 调用预约接口。

## 五、现场加号

加号是否开放由科室和医生根据当日情况决定。知识库不承诺任何患者一定能够加号，也不存在支付个人费用即可保证加号的通用规则。

患者到现场提出加号申请时，仍需完成身份核验和现场登记。已经排队不代表申请获批；获得加号后还要以系统生成的有效就诊记录为准。

## 六、候补与加号区别

候补是患者对已满号源登记等待，资源释放后按照候补规则处理；现场加号是另一种业务安排。候补成功、收到候补通知和最终确认可能是不同状态，不能与加号混称。

患者同时存在候补和其他有效预约时，应根据医院规则处理冲突。聊天助手不能为了提高成功率重复创建多个写操作。

## 七、取消与退款

患者主动取消、医生停诊和系统异常取消可能使用不同原因码。是否记爽约、如何退费和多久入账，应根据真实预约与支付记录判断，不能用本文档替代门诊预约退费规则。

文字输入“确认”不能直接执行取消或创建预约。系统应返回现有确认卡并提示点击按钮；用户说“算了”时应真正拒绝当前等待确认的动作。

## 八、隐私与安全

医生排班可以作为公共业务信息查询，但患者预约、候补和联系方式属于个人信息。工作人员不得根据姓名向无权人员披露某患者预约了哪位医生。

知识库只描述流程和安全边界。实时停诊、号源、候补位置和预约结果以医院系统为最终权威来源。
