## 2. Top 5 实测结果

### 2.1 v1 初始 13 文档、13 chunk

| 策略 | Recall@5 | Precision@5 | MRR | nDCG@5 | 负例空召回率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Elasticsearch BM25 | 1.0000 | 0.2000 | 0.9583 | 0.9692 | 0.0000 |
| BGE-M3 Vector | 1.0000 | 0.2000 | 0.9861 | 0.9897 | 0.0000 |
| BM25 + Vector RRF | 1.0000 | 0.2000 | 0.9861 | 0.9897 | 0.0000 |

36 条正例在三种策略下均于 Top 5 命中目标文档。Vector 与最小 RRF 的排序指标相同，均略高于 BM25；当前小型、单 chunk 为主的数据集上，RRF 尚未表现出额外收益。

当前每个正例只标注一个正确文档，且统一取 Top 5，因此全部命中时 Precision@5 的理论值就是 `1 / 5 = 0.2`。该指标主要用于后续同一数据集和同一口径下的回归比较，不能单独解释为检索质量只有 20%。

### 2.2 v1 扩充后 25 文档、37 chunk

固定评测问题、相关文档标注、Top K 和检索参数均保持不变。编号 13～24 不包含直接对应的评测题，只作为相似主题、例外条件和多 chunk 干扰项。

| 策略 | Recall@5 | Precision@5 | MRR | nDCG@5 | 负例空召回率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Elasticsearch BM25 | 1.0000 | 0.2000 | 0.9074 | 0.9312 | 0.0000 |
| BGE-M3 Vector | 1.0000 | 0.2000 | 0.9583 | 0.9692 | 0.0000 |
| BM25 + Vector RRF | 1.0000 | 0.2000 | 0.9722 | 0.9795 | 0.0000 |

扩充后 36 条正例仍全部进入 Top 5，但 MRR 和 nDCG 明显不再饱和。RRF 的 MRR 比 Vector 高 `0.0139`，nDCG@5 高 `0.0103`；这证明在原有问题上，加入相似制度干扰后，融合两路排名产生了可测量的排序收益。该结果属于 v1 历史基线，当时新增文档还没有自己的标注问题。

### 2.3 v2 80 条评测集

v2 为编号 13～24 的每份新增文档补充 3 条正例，并增加 4 条负例。Top K、文档、索引和检索参数保持不变。

| 策略 | HitRate@5 | Recall@5 | 标准 Precision@5 | MRR | nDCG@5 | 负例空召回率 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Elasticsearch BM25 | 1.0000 | 1.0000 | 0.2000 | 0.9056 | 0.9296 | 0.0000 |
| BGE-M3 Vector | 0.9861 | 0.9861 | 0.1972 | 0.9514 | 0.9605 | 0.0000 |
| BM25 + Vector RRF | 0.9861 | 0.9861 | 0.1972 | 0.9514 | 0.9605 | 0.0000 |

BM25 的 72 条正例全部进入 Top 5，但首个正确文档平均排名不如 Vector。Vector 与 RRF 都漏掉 `rag-057`；该题的 BM25 正确 chunk 排第 1、Vector 正确文档的另一 chunk 排第 10，按 `chunkId` 融合后目标 chunk 在 Hybrid 排第 6。这暴露了当前 chunk 级 RRF 在“两路命中同一文档的不同 chunk”时无法合并文档级证据的限制。

v2 的结论与 v1 不同：RRF 在完整 80 题上暂未优于 Vector，因此仍不切换患者默认策略。

### 2.4 v3 104 条多正例评测集

v3 保留全部 v2 用例，新增 24 条必须联合 2～3 份制度才能完整回答的跨制度问题。多正例不是为每题机械增加相关文档：明确事实题仍保留一个权威来源，只有问题的不同子问题确实由不同制度回答时才标注多个相关文档。

| 策略 | HitRate@5 | Recall@5 | 标准 Precision@5 | MRR | nDCG@5 | 负例空召回率 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Elasticsearch BM25 | 1.0000 | 0.9965 | 0.2542 | 0.9188 | 0.9318 | 0.0000 |
| BGE-M3 Vector | 0.9896 | 0.9792 | 0.2500 | 0.9566 | 0.9562 | 0.0000 |
| BM25 + Vector RRF | 0.9896 | 0.9809 | 0.2500 | 0.9635 | 0.9603 | 0.0000 |

HitRate 与 Recall 不再等价：三种策略都至少命中了 24 条跨制度问题中的一个相关文档，但 BM25 完整召回 23/24，Vector 与 Hybrid 各完整召回 22/24。具体的不完整召回如下：

- BM25：`rag-104` 命中 3 个相关文档中的 2 个。
- Vector：`rag-083`、`rag-085` 各命中 2 个相关文档中的 1 个。
- Hybrid：`rag-083` 命中 1/2，`rag-104` 命中 2/3。

标准 Precision@5 从单正例数据集的约 `0.20` 上升到约 `0.25`，现在能够反映一次查询召回多个相关制度的收益，但仍受人工相关性判断池不完整的限制。Hybrid 相比 Vector 的 Recall、MRR 和 nDCG 有小幅提升，但仍未超过 BM25 的覆盖率，暂不足以据此切换患者端默认检索策略。

## 3. 负例结论

v3 的 8 条负例在 BM25、Vector 和 RRF 下都返回了结果，因此负例空召回率均为 0%。原因不同：

- BM25 会因为“医院、预约、报告”等通用词或中文单字命中而返回文档。
- kNN 必然会从已有向量中返回距离最近的候选，即使候选并不足以回答问题。
- RRF 只融合两路排名，不负责判断知识库是否真的存在答案。

这说明“检索有结果”不能直接解释为“知识库有答案”。后续阶段需要在固定评测集上校准：

- Vector 的最低相似度阈值。
- BM25 的最低分、最少匹配条件或其他可靠拒答信号。
- Hybrid 后的统一无答案判定。
- 最终 RAG 回答是否严格依据引用资料拒答。

本阶段只建立基线，不根据 8 个负例临时硬编码关键词或阈值。

## 4. 已实现的可重复评测能力

- 固定数据集：`backend/src/main/resources/evaluation/rag-evaluation-v3.json`
- 管理员评测接口：`POST /api/agent/admin/knowledge/evaluations/retrieval`
- 请求示例：

```json
{
  "strategy": "BM25",
  "limit": 5
}
```

- 支持策略：`VECTOR`、`BM25`、`HYBRID`
- 返回指标：HitRate@K、Recall@K、标准 Precision@K、MRR、nDCG@K、负例空召回率和逐问题结果。
- 管理员“知识检索测试”页面可选择 Vector、BM25 或 BM25 + Vector RRF，并可直接运行 104 条固定评测。
- 患者角色访问评测接口返回 HTTP 403。

## 5. 当前限制

- 评测问题根据虚构制度人工编写，仍可能比真实患者问法更规整，指标可能偏高。
- 编号 01～24 每份文档已有 3 条单文档正例，另有 24 条跨制度多文档正例；尚未进行精确 chunk 级相关性标注。
- 当前多正例来自人工核对制度内容，尚未把三种检索器 Top 10 候选的并集全部纳入人工判断池，Precision 仍可能把未标注但有辅助价值的文档视为不相关。
- 当前是文档级标注，不是精确 chunk 级标注。
- 尚未测量 P50/P95 检索耗时。
- 最小 RRF 当前由 Java 对两次 Elasticsearch 查询结果做排名融合，尚未改成 Elasticsearch 原生单次 RRF 请求。
- 当前 RRF 固定每路候选窗口为 50、`rank_constant=60`，尚未做参数实验。
- 尚未对阈值、切块和 Reranker 做实验。
- 负例空召回率只是检索层信号，最终安全性仍需结合 RAG 引用和拒答测试。

## 6. 下一步决策

下一步保持现有 Top 5 指标口径，不增加 Top1/Top3，继续补充更长制度、真实口语改写和完整相关性判断。继续使用同一评测接口比较：

1. Vector
2. BM25
3. BM25 + Vector + RRF

完整 v3 结果中 Hybrid 比 Vector 的 Recall、MRR 和 nDCG 略高，但提升很小，且多正例完整召回仍为 22/24，因此暂不将 Hybrid 设为患者 RAG 默认策略。后续应先补全候选判断池，并决定是否增加文档级聚合或限制同文档 chunk 数，再重复验证。
